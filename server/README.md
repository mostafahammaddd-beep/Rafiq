# خادم الفحص الدقيق لتطبيق «رَفِيق»

يشغّل نموذج **quran-muaalem** (مفتوح المصدر، رخصة MIT): يحوّل الصوت الخام إلى **فونيمات** بلا نموذج لغوي،
ثم يقارنها بالنطق المرجعي للآية، فيكشف أخطاء الحروف والتشكيل والتجويد (المدود، الغنة، القلقلة…).
هذا هو الفرق الجوهري عن «التعرّف على الكلام» العام الذي يخمّن الكلمة الأقرب ويُصحّح خطأك تلقائياً.

## التشغيل

### أ) Hugging Face Space (مجاني — لكنه بطيء على CPU)
1. أنشئ Space جديداً واختر SDK = **Docker**.
2. ارفع كل ملفات هذا المجلد إلى جذر الـ Space: `Dockerfile` و `start.sh` و `patch_settings.py` و `README.md`.
3. انتظر البناء، ثم أول إقلاع (تنزيل النموذج ≈ 2.4GB، ويتكرر بعد كل إعادة تشغيل).
4. افتح **Logs** وتأكد من ظهور أسطر `[patch_settings]` وأن: `accelerator` = cpu و `max_audio_seconds` = 60.
   إن لم تظهر القيم المعدَّلة فالإعدادات لم تُطبَّق — أرسل لي السجل.
5. الصق العنوان `https://<حسابك>-<اسم-الـSpace>.hf.space` في حقل «عنوان خادم الفحص الدقيق» داخل التطبيق.

### ب) حاسوبك (أسرع، خصوصاً مع GPU)
```
docker build -t rafiq-server .
docker run -p 8001:8001 rafiq-server
```
العنوان في التطبيق: `http://<عنوان-IP-الحاسوب>:8001` (الجوال والحاسوب على نفس الشبكة).

## اختبار الخادم بدون التطبيق
```
curl -X POST http://localhost:8001/correct-recitation \
  -F error_ratio=0.2 -F sura_idx=2 -F aya_idx=255 -F "file=@rec.wav"
```
يجب أن يعود JSON فيه `errors` و `uthmani_text`. الحقلان `sura_idx` و `aya_idx` يعملان فقط في نسخ المشروع
التي تدعم التلميح؛ وإلا يُتجاهلان ويبحث الخادم عن الآية في المصحف كله (وآية الكرسي نصّها فريد فلا إشكال).

## تنبيهات
- الدقة المنشورة للنموذج على أخطاء متعلّمين حقيقية: F1 للتجويد ≈ 75.8% — فهو يفوته بعض الأخطاء وقد ينبّه خطأً.
- الصوت يُرسل إلى الخادم الذي تشغّله أنت فقط.
